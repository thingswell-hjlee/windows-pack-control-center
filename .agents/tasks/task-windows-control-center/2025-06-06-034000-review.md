# Local Web Control Center for AIBox device management

A greenfield .NET 8 + React + TypeScript application that serves as a local dashboard for monitoring AI camera devices (AIBox units) on Windows. The gateway connects to per-device MQTT brokers, normalizes incoming safety events (falls, intrusions, PPE violations), persists them to SQLite, and pushes real-time updates to the browser via SignalR. The frontend provides CRUD for devices/cameras, event browsing with filtering and pagination, acknowledgment workflows, and CSV export.

Watch for: MQTT credentials stored and transmitted in plaintext with no authentication on the API (confirmed), unbounded reconnection recursion in the MQTT disconnect handler (confirmed), and a CSV export endpoint that loads the entire result set into memory without size limits (confirmed).

## High-level view

The system is a single-process gateway that multiplexes MQTT connections to many AIBox devices, each running its own broker. A bounded channel architecture with DropOldest back-pressure separates the MQTT ingestion layer from the event normalizer and status updater. The reconnect logic for MQTT clients re-reads device state from the database before reconnecting, but contains a recursive call path that can stack-overflow or leak tasks under sustained broker unavailability.

All REST endpoints are unauthenticated. Any process on the local network can create, delete, or modify devices, acknowledge events, and export all event history. MQTT and ONVIF passwords for connected devices are readable via `GET /api/devices` with no redaction.

The frontend's `acknowledgeEvent` call hardcodes the user as `'admin'` rather than prompting, which means the ack audit trail is meaningless. The shared SignalR singleton connection gets torn down when any component using `useSignalR` unmounts, breaking real-time updates for the rest of the app.

<details>
<summary>Issues (7)</summary>

1. **MQTT disconnect recursion** — `ConnectToDevice` is called recursively from the `DisconnectedAsync` handler with no retry cap. Under sustained broker failure this will stack-overflow or leak tasks. Add a bounded retry loop or a reconnect backoff strategy with a maximum attempt count.
2. **Credential exposure via API** — `GET /api/devices` returns `mqtt_password`, `onvif_password`, and `mqtt_username` in plaintext. Either redact sensitive fields in the response DTO or add a separate privileged endpoint for credential access.
3. **No authentication on any endpoint** — All API endpoints and the SignalR hub are open. If the deployment is reachable over the LAN (port 8088 on 0.0.0.0), any client can manipulate devices and events. Add at minimum a shared-secret or token-based auth gate.
4. **Unbounded CSV export** — The `/api/events/export/csv` endpoint materializes the entire filtered result set in memory. A large event history could OOM the process. Add pagination or streaming.
5. **Hardcoded 'admin' user for acknowledgment** — The frontend always sends `'admin'` as `ack_user`, making the audit column useless. Wire up a user identity prompt or a configurable operator name.
6. **Missing TsMs index** — Event queries filter and sort on `TsMs` but the DB context only indexes `Timestamp` (the string column). Add an index on `TsMs` for query performance.
7. **SignalR singleton connection teardown** — The `useSignalR` hook calls `stopConnection()` on cleanup, but the connection is a module-level singleton. If multiple components mount the hook (currently `AppContent` and `Events`), the first unmount tears down the shared connection.

## MQTT connection lifecycle and reconnection

When `DisconnectedAsync` fires, it waits 5 seconds and then calls `ConnectToDevice(freshDevice, stoppingToken)`. That method registers a new `DisconnectedAsync` handler on the new client instance, which will again call `ConnectToDevice` on the next disconnect. If the broker is unreachable, this produces an unbounded chain of async continuations — each one creating a new `IMqttClient`, failing to connect (throwing), and the exception handler logging and returning. The client never gets added to `_clients`, so the next 30-second poll will also attempt connection, compounding the leak.

```csharp
// MqttReceiverService.cs — recursive path
client.DisconnectedAsync += async e =>
{
    ...
    await ConnectToDevice(freshDevice, stoppingToken); // recursive
};
```

A bounded retry loop (3-5 attempts with exponential backoff) followed by giving up and letting the 30-second poll handle rediscovery would be safer.

## Credential exposure and authentication posture

The REST API returns the full Device entity including `mqtt_password` and `onvif_password`:

```csharp
// DevicesEndpoints.cs
group.MapGet("/", async (AppDbContext db) =>
{
    var devices = await db.Devices.OrderByDescending(d => d.CreatedAt).ToListAsync();
    return Results.Ok(devices);  // includes mqtt_password, onvif_password
});
```

The server binds `0.0.0.0:8088` without TLS. For a control center managing physical security cameras, credentials for the camera infrastructure are one `curl` away from any process on the network. There is no authentication middleware — no API key, no cookie, no bearer token. The CORS policy restricts origins during development but provides no security in production since the server also serves the SPA from `wwwroot`.

## CSV export memory profile

The export endpoint loads all matching events into a list, serializes them fully to a `StringWriter`, converts to a byte array, and returns:

```csharp
var events = await query.OrderByDescending(e => e.TsMs).ToListAsync();
using var writer = new StringWriter();
using var csv = new CsvWriter(writer, CultureInfo.InvariantCulture);
csv.WriteRecords(events);
var content = writer.ToString();
return Results.File(System.Text.Encoding.UTF8.GetBytes(content), "text/csv", "events_export.csv");
```

For a deployment that ingests safety events 24/7 over months, this could mean millions of rows materialized in memory simultaneously. A streaming response using `IAsyncEnumerable` piped through a `PipeWriter` would bound memory usage regardless of result set size.

## Missing database index on TsMs

All event queries — the paginated list, the dashboard "today" count, and the CSV export — filter or sort by `TsMs`. The `AppDbContext` indexes `Timestamp` (the string-formatted column) but not `TsMs`:

```csharp
entity.HasIndex(e => e.Timestamp);  // indexed
// e.TsMs — not indexed, used in WHERE and ORDER BY
```

As the event table grows, these queries will degrade to table scans.

## SignalR connection shared-singleton lifecycle

The frontend's `signalr.ts` module holds a single `connection` reference. `useSignalR` is invoked in both `AppContent` (for the connection indicator) and `Events` (for live event refresh). When `Events` unmounts (navigating away), its cleanup calls `stopConnection()`, which stops the shared hub connection — disconnecting the `AppContent` indicator and any other listener.

Cleanup should be reference-counted or moved exclusively to the app shell's lifecycle rather than per-component.

## Near-capacity log flood

The channel capacity warning fires on every incoming message once the 90% threshold is crossed. Under sustained load this becomes a log flood rather than a useful signal. A rate-limited warning (e.g., once per minute via a timestamp check) would be more operationally useful.
